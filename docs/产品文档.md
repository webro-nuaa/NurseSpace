## 一、产品概述

### 1.1 产品定位

NurseSpace 是面向医院护理单元的**案例驱动型培训与考核系统**，以真实临床案例文档为核心资产，覆盖"案例管理 → 在线学习 → AI 评分 → 错题追踪 → 薄弱点诊断 → 在线考试 → 讨论交流"的完整培训闭环。

### 1.2 要解决的问题

| 痛点 | 本产品的对应能力 |
|------|------------------|
| 案例教学文档分散在教员个人电脑，检索复用成本高 | 案例库统一管理，支持 Word 文档上传解析、批量导入（docx/xlsx）、导出 |
| 人工评分主观、滞后、反馈质量不可控 | AI 三级降级评分（OpenAI / 智谱 GLM / 本地匹配），提交后异步返回评分与逐条反馈 |
| 护士无法系统了解自身薄弱环节 | 错题本自动归集 + AI 薄弱点诊断（基于错题内容分析，非简单统计） |
| 培训数据难以资产化 | 学习记录、积分流水、考试成绩全量入库，管理端数据看板汇总 |

### 1.3 用户角色

系统在 [models.py](../models.py#L23) 中定义两种角色，由 `users.role` 字段（`nurse` / `admin`）区分：

| 角色 | 职责 | 登录方式 |
|------|------|----------|
| **护士** | 案例学习与答题、错题本、薄弱点分析、参加考试、积分兑换、答案讨论、知识问答 | 账号密码登录（管理员批量导入或自主注册） |
| **管理员** | 用户管理、案例库建设（含批量上传/xlsx 导入）、考试组卷发布、知识库维护、AI 参数配置、数据看板 | 账号密码登录（首个管理员由部署脚本自动创建） |

## 三、核心业务流程

### 3.1 案例学习与 AI 评分（主流程）

```
护士选择案例 → 进入考核站点 → 阅读（考核任务 + 病情报告 + 提问）
    → 输入文字作答 或 浏览器录音转文字作答
    → 提交答案
    → 服务端创建学习记录，异步线程池排队 AI 评分
        评分链路：GLM/OpenAI → 失败降级 → 本地文本匹配兜底
    → 返回总分 + 逐条标准答案比对反馈
    → ≥80 分 +10 积分 / ≥90 分 +20 积分
    → <60 分自动写入错题本
```

评分与积分阈值定义于 [services/evaluation.py#L10-L14](../services/evaluation.py#L10)。

### 3.2 薄弱点诊断闭环

```
错题本数据 + 低分记录 → AI 诊断 Agent 生成（薄弱点 + 改进建议）
    → 结果以 JSON 文本持久化（每用户一份，可重新生成覆盖）
    → 护士端展示诊断报告
```

### 3.3 在线考试流程

```
管理员创建考试（起止时间、时长）→ 从案例库挑选题目组卷 → 发布
    → 护士在时间窗口内进入考试 → 逐题作答（支持语音）→ 提交
    → 各题 AI 评分 → 汇总成绩 → 管理端查看成绩明细
```

### 3.4 案例资产入库流程

```
教员编写 Word 案例（约定格式）→ 管理员批量上传（或 xlsx 导入）
    → docx 解析器提取站点/标准答案 → 入库 + 文件落盘
    → 护士端立即可见可学
```

## 五、产品审核发现

从产品视角审核代码后，发现以下与产品宣称不符或体验隐患的问题：

1. **评论功能宣称支持"知识答案讨论"，实际数据模型不支持。**
   [models.py#L297-L298](../models.py#L297) 注释写明 `content_type` 支持 `station_answer`（站点答案）与 `knowledge_answer`（扩展知识答案）两类，但枚举只定义了 `station_answer`，且 API 层已按此白名单校验（[routes/api.py#L360](../routes/api.py#L360)）。**评论功能实际只能用于站点答案**，产品宣称与实现不一致，需二选一：扩展枚举（加迁移）落地该功能，或修正产品描述。

2. **AI 评分队列满时用户直接收到"请稍后重试"，无重试引导。**
   [services/evaluation.py#L33-L40](../services/evaluation.py#L33) 设计了有界队列防止过载（合理），但产品层面对"被拒后的重试体验"没有任何兜底（无自动重试、无状态轮询提示）。高并发考试提交场景下建议增加前端重试或排队提示。

3. **积分只有"获得"没有"消耗"场景。**
   积分体系仅记录奖励流水（[services/points.py](../services/points.py)），产品上没有积分兑换/商城功能。若规划中有兑换能力，需补充兑换表与扣减逻辑；若没有，积分仅是排行榜性质，产品文档应如实描述。

4. **薄弱点诊断每用户仅保留最新一份**（[models.py#L283](../models.py#L283) `user_id` 唯一约束），无法回看历史诊断、无法体现成长趋势。产品若宣传"能力成长追踪"，当前实现只支持"当前状态快照"。

5. **学习记录允许同一用户对同一站点重复提交多条**（[models.py#L141-L151](../models.py#L141) 无唯一约束，与错题表的唯一约束形成对比），是否覆盖旧分取决于前端交互，需产品确认期望行为（保留最佳成绩 or 保留全部历史）。
