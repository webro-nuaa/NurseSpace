## 三、应用装配与请求生命周期

[app.py#L38-L174](../app.py#L38) 的 `create_app()` 按以下顺序装配：

1. 加载 [config.py](../config.py)（全部配置项从环境变量读取，生产必填项缺失直接抛错，见 `_require_env`）；
2. 初始化请求追踪 ID（[utils/logging.py](../utils/logging.py)，响应头返回 `X-Request-Id`）；
3. `ProxyFix` 信任 Nginx 的 `X-Forwarded-*`；
4. 初始化 `db` / `migrate`，并通过 `app.extensions` 注入共享单例：`ai_evaluator`、`knowledge_service`（依赖注入点，[app.py#L59-L64](../app.py#L59)）；
5. 依次初始化 login / jwt / csrf / CORS（带凭据与 `*` 通配互斥检查）/ Cache（Redis 或 SimpleCache 降级）/ Limiter；
6. 统一 401 未授权处理：AJAX/JSON 请求返回 401 JSON，页面请求重定向登录页（[app.py#L103-L112](../app.py#L103)）；
7. 全局错误处理器（400/404/405/413/500，500 时回滚 session 并记日志）；
8. HTML 响应统一加 `no-cache` 头，防止发版后浏览器缓存旧页面配新 JS；
9. 注册 5 个蓝图：`/auth`、`/nurse`、`/admin`、`/api`、main（页面路由）；
10. `/api` 蓝图整体豁免 CSRF（[app.py#L157](../app.py#L157)）——因其认证不依赖浏览器 Session Cookie 而靠 JWT Header，豁免合理；
11. `/uploads/<path>` 由 Flask 直接提供大文件下载（本地无 nginx 场景）；生产 nginx 对 `/uploads/` 启用 `auth_request`，经 [routes/media.py](../routes/media.py) 的 `/api/media/auth` 子请求校验登录态后才放行静态文件。

## 五、数据模型（15 张表）

```
users ──┬─< learning_records >── stations ──> cases ──> case_categories
        ├─< wrong_questions  >── stations      ├──< stations
        ├─< exam_records     >── exams         ├──< exam_questions >── exams
        ├─< point_records      │               ├──< extension_videos
        ├─< comments           │               └──< extension_links
        ├─< comment_likes ───< comments（自关联回复 parent_id）
        └─< comment_reports ─< comments

独立配置表：ai_settings（单例行，AI Provider/Key 加密）
           baidu_asr_keys（ASR 密钥，加密）
           weakness_analysis（每用户一份诊断 JSON）
```

**关键约束**（[models.py](../models.py)）：

- `wrong_questions`：`(user_id, station_id)` 唯一（L162）；
- `learning_records`：`(user_id, station_id)` 唯一（重做时由服务层更新原记录，不保留历史）；
- `exam_records`：`(exam_id, user_id)` 唯一（一人一考一场，与 start_exam 业务守卫双保险）；
- `comment_likes` / `comment_reports`：`(user_id, comment_id)` 唯一（L348、L380）；
- `comments`：三个复合索引（L327-L331）；
- `cases` 删除级联清理 stations/exam_questions/videos/links（L83-L86）；`Exam.records`/`ExamQuestion.answers` 级联清理，考试删除链在 ORM 层完整；
- `Station.exam_answers` **不级联**：答卷生命周期挂在 `ExamRecord` 下，删除站点若被答卷引用由 FK RESTRICT 拦截，保护考试历史（案例删除会返回"该案例已被考试引用"）；
- 删除案例时服务层显式清理站点评论及点赞/举报（评论对站点是逻辑多态引用，无 FK）；
- `users.role` / `status`、案例难度/类型、站点类型均用 MySQL Enum；
- API Key 类字段（`ai_settings.*_key`、`baidu_asr_keys.*`、`users.knowledge_key`）统一 `String(500)` 容纳 Fernet 密文，**加密存储**；
- 时间戳统一 naive UTC（`_utcnow`）；考试时间窗（`exams.start_time/end_time`）由管理员输入的本地时间（`Config.TIMEZONE`，默认 Asia/Shanghai）经 `utils/time_utils.parse_local_to_utc` 转为 UTC 后存库。

**迁移**：Alembic 管理，最新迁移 `94dc4402a203` 补齐学习/考试记录唯一约束并将存量考试时间窗换算为 UTC；[migrations/env.py](../migrations/env.py) 从 Flask 应用读取连接串。

## 六、关键机制

| 机制 | 设计 |
|------|------|
| **双通道认证** | 页面路由走 Flask-Login Session；`/api` 走 JWT Header（`@jwt_required`）；[utils/auth.py](../utils/auth.py) 提供两者兼容的装饰器。`users.token_version` 支持 JWT 失效 |
| **CSRF 策略** | 浏览器 Session 路由全开 CSRF；`/api`（JWT 认证）豁免；前端 [common.js#L24-L34](../static/js/common.js#L24) 自动带 Token |
| **多层限流** | Nginx（登录/普通 API/上传分区限速）+ Flask-Limiter（登录 5/分钟，Redis 存储） |
| **密钥安全** | 所有 AI/ASR Key 经 Fernet 加密入库（[utils/crypto.py](../utils/crypto.py)），`ENCRYPTION_KEY` 缺失启动即报错；有往返加解密单测（[tests/test_security.py#L109-L139](../tests/test_security.py#L109)） |
| **AI 评分降级链** | GLM → OpenAI → 本地文本匹配（[utils/ai_evaluator.py](../utils/ai_evaluator.py)）；提交后进入有界线程池异步执行，队列满返回 429 语义错误 |
| **缓存降级** | Redis 不可用时 Cache 降级 SimpleCache、限流可关闭，本地开发零依赖 |
| **向量知识库** | ChromaDB 持久化 + SQLite WAL（多 worker 并发安全）+ `database is locked` 指数重试（[utils/rag.py#L34-L62](../utils/rag.py#L34)） |
| **文件处理** | 上传 128MB 上限、类型校验、docx 解析、xlsx 模板导入、Word 导出 |

## 七、部署与运维

- **Dockerfile**：多阶段构建（builder 装依赖 → runtime 仅拷贝产物），非 root 用户运行（`COPY --chown` 授权），暴露 8000；`.dockerignore` 排除备份/binlog/测试/文档等一切非运行内容；
- **entrypoint.sh** 启动五步（[entrypoint.sh](../entrypoint.sh)）：等 MySQL 就绪（业务账号，不持有 root 凭据）→ **统一 `alembic upgrade head`**（空库由完整 baseline 建表，无 create_all 分支）→ 创建初始管理员（fail-fast，失败即退出）→ 初始化默认 AI 配置（fail-fast）→ 检查/下载 Chroma ONNX 模型缓存 → `exec gunicorn`；
- **部署入口唯一**：[deploy.sh](../deploy.sh)（拉代码 → 以 git 短哈希 tag 构建镜像 → `up -d --wait` 阻塞等健康检查 → 失败报错退出；`rollback <tag>` 支持回滚历史镜像）；
- **三套编排**：`docker-compose.yml`（生产：MySQL+Redis+app+nginx，健康检查、资源限制、front/back 网络分层、app 凭据最小化不含 root 数据库密码、镜像版本固定）、`docker-compose.local.yml`（本地）、`docker-compose.e2e.yml`（隔离验收栈，5001 端口）；
- **Nginx**：TLS（安全协议白名单）、安全响应头片段（snippets，规避 location 内 add_header 继承丢失）、`/uploads/` 鉴权代理、静态/上传资源缓存、按路由限流与超时；
- **备份**：[scripts/backup.sh](../scripts/backup.sh)（single-transaction 全量 + 30 天滚动清理），`scripts/install_backup_cron.sh` 安装每日 02:00 定时任务。

## 九、架构评估（本次审核结论）

### 9.1 总体结论

**架构总体合理，主链路清晰，安全与生产化设计超出同类项目平均水平；主要短板集中在"业务逻辑层"与"前端工程化"两处，属于可演进的债务而非结构性错误。**

打分参考：后端结构 8/10，数据建模 8.5/10，安全设计 9/10，部署运维 8.5/10，服务分层 5.5/10，前端工程化 4.5/10。

### 9.2 做得好的地方

1. **应用工厂 + 蓝图按角色划分**：`auth/nurse/admin/api/main` 边界清楚，admin/nurse 内部再按功能拆文件，路由文件最大 660 行、多数在 300 行以内，可读性尚可。
2. **配置全部环境变量化 + 生产强制校验**：`_require_env` 让缺配置在启动时失败而非运行时；Redis/限流均可降级关闭，本地开发体验好。
3. **安全设计系统化**：Session+JWT 双通道职责分明、CSRF 豁免理由正确、双层限流、密钥加密入库且有测试覆盖、ProxyFix、请求追踪 ID——安全闭环完整。
4. **数据建模细致**：唯一约束防重复错题/重复点赞、复合索引匹配查询模式、级联删除完整（cases → stations → answers）、Enum 用在取值固定的字段上。
5. **生产韧性**：AI 评分有界线程池防 OOM、Chroma WAL + 锁重试、健康检查、全局 500 回滚 session、HTML no-cache 防发版缓存错位。
6. **entrypoint 启动自愈**：建库/迁移/管理员/模型缓存全自动，支持全新部署与升级两种路径。

### 9.3 问题清单（按优先级）
